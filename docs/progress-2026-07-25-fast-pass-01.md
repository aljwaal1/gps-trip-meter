# تمريرة تسريع gps-trip-meter — 2026-07-25

## ما تمت مراجعته
- بنية Flutter والملفات الرئيسية كما هي موثقة في README.
- `lib/services/trip_session.dart`: دورة حياة الرحلة، GPS، الحفظ، الاستعادة، وخدمة الخلفية.
- `pubspec.yaml`: حزم الموقع والتخزين والخدمة الأمامية والصلاحيات.
- `.github/workflows/build-apk.yml`: Manifest المُنشأ أثناء البناء، التحليل، بناء APK، ودفع المخرجات.

## المشكلة الأساسية
عند وصول خطأ من `Geolocator` كان التطبيق يغير `running` إلى false ويوقف المؤقتات فقط. لم يكن يلغي اشتراك الموقع أو يوقف Foreground Service أو يضمن حفظ آخر حالة قابلة للاستعادة قبل إيقاف الرحلة منطقيًا.

## ما تم تغييره
- إضافة مسار async لتنظيف خطأ GPS.
- حفظ آخر حالة نشطة إجباريًا قبل تغيير `running`.
- إلغاء اشتراك الموقع وتصفير مرجعه.
- إيقاف مؤقتات الواجهة والحفظ.
- إيقاف Foreground Service.
- إبقاء الحالة المحفوظة قابلة للاستكمال بدل فقد الرحلة.
- إضافة اختبار عقد يمنع رجوع الخلل.
- تشغيل `flutter test` داخل GitHub Actions.
- إضافة `paths-ignore` لمخرجات APK لمنع حلقات بناء غير ضرورية.
- تقوية Manifest أثناء البناء بـ `allowBackup=false` و`usesCleartextTraffic=false`.

## ما بقي
- اختبار رحلة حقيقية في الخلفية على جهاز Android.
- اختبار رفض صلاحية الموقع الدائمة ثم استكمال التتبع الأمامي.
- مراجعة دقة ترشيح نقاط GPS بعد جمع بيانات حقيقية من المشي والسيارة.
- التحقق من اكتمال GitHub Actions وظهور APK جديد.
